# V1.2 Roadmap — Persistent Intelligence Memory & GraphRAG

## 1. Goal

Extend Strategic Intelligence from a single-case research system into a persistent intelligence system that accumulates knowledge across user-selected companies.

Every company researched by the user should contribute reusable intelligence to a persistent knowledge base.

The accumulated intelligence will then be projected into a knowledge graph and used for evidence-backed GraphRAG retrieval.

---

## 2. Core User Scenario

The user researches companies over time:

Capgemini
→ Spotify
→ H&M
→ Ericsson
→ Volvo
→ ...

The system must remember previously researched companies and their governed intelligence.

A future research request for an existing company should load stored intelligence first instead of automatically repeating the same web research.

New web research must happen only when explicitly requested or when a defined freshness policy requires it.

---

## 3. Non-Negotiable Rules

### User-Controlled Company Set

The system must never invent or automatically choose target companies.

Only companies explicitly entered by the user become tracked companies.

Research order must be preserved.

Example:

01. Capgemini
02. Spotify
03. H&M
04. Ericsson

### Persistent Intelligence

Research results must survive individual cases and application restarts.

The system must preserve:

- Company
- Research runs
- Sources
- Evidence
- Claims
- Verification results
- Governance decisions
- Entities
- Relationships
- Research timestamps

Final generated briefs alone are not sufficient as persistent memory.

### Memory First

When the user requests a company already present in memory:

Company Request
→ Check Persistent Memory
→ Load Existing Intelligence
→ Show Existing Intelligence

The system must not automatically repeat web research.

Explicit refresh remains available.

### Evidence First

The knowledge graph is not the source of truth.

Canonical trust remains:

Source
→ Evidence
→ Claim
→ Verification
→ Governance

Graph entities and relationships must remain traceable back to this chain.

### Governed Graph

Unsupported or blocked information must not silently become graph knowledge.

Every graph relationship must preserve provenance such as:

- relationship_id
- source_entity_id
- target_entity_id
- relation_type
- claim_id
- evidence_id
- source_id
- governance_status
- researched_at

V1.2 reuses the existing V1 Source, Evidence, Claim, Verification,
GovernanceDecision, WorkflowRun, checkpoint, and audit records. G02 adds only
the missing durable company-memory index/ordered membership and cross-case run
association; G03/G04 add entity and relationship records; G05 adds a graph
projection/index. None may become a duplicate trust store.

The smallest temporal contract for new relationship/projection records is:

```text
relationship_id   required stable relationship projection ID
research_run_id   required persisted WorkflowRun reference
created_at        required timezone-aware record timestamp
valid_from        optional supported validity start
valid_to          optional supported validity end
superseded_by     optional replacement relationship ID
temporal_status   CURRENT | STALE | CONFLICTING | SUPERSEDED
```

Use existing `FreshnessStatus`, `VerificationStatus`, and PASS/RESTRICT/BLOCK
semantics. CURRENT means eligible and not stale at query `as_of`; STALE means
support freshness is stale; CONFLICTING means governed support disagrees;
SUPERSEDED means replaced by `superseded_by`. BLOCK always excludes usable
retrieval. Stale, conflicting, and superseded records remain inspectable and
traceable rather than being deleted or silently collapsed.

# Card Roadmap

## G01 — Graph Intelligence Contract

**Dependencies:** None. G01 is the contract gate for all later Cards.

### Goal

Define exactly what GraphRAG is responsible for before implementation.

### Deliverables

Define:

- supported entity types
- supported relationship types
- memory behavior
- refresh behavior
- provenance requirements
- supported query categories
- evaluation dataset
- success criteria

Initial entity scope:

- Company
- Person
- Technology
- Project
- Event

Initial relationship scope:

- LEADS
- PARTNERED_WITH
- DEVELOPS
- USES
- INVOLVED_IN

### Exit Criteria

GraphRAG scope is bounded and testable.

The contract also defines temporal provenance, freshness, supersession, and
inspectable conflict handling; claims must never be silently collapsed across
time or disagreement.

---

## G02 — Persistent Company Memory

**Dependencies:** G01 only.

### Goal

Make researched companies reusable across future cases.

### Capabilities

Store:

- user-entered company identity and exact/normalized duplicate keys only
- first researched date
- last researched date
- research history
- every reusable durable research artifact: research runs, Sources, Evidence,
  Claims, Verification Results, Governance Decisions, and their relationships

Maintain user-entered company order.

### Required Behavior

Existing company request:

Request
→ Memory Lookup
→ Existing Intelligence

No automatic re-search.

Memory is always checked first. A new company may undergo its initial research;
for an existing company, web research occurs only on an explicitly requested
Refresh. Refresh creates a new run, preserves all prior runs and temporal
provenance, and never overwrites history. G02 owns
exact/normalized company duplicate handling only; true entity resolution for
people, technologies, projects, events, and ambiguous identities belongs to
G03.

### UI State

Example:

Companies in Memory

01 Capgemini   Researched
02 Spotify     Researched
03 H&M         Researched

### Exit Criteria

Restarting the application does not lose previously researched intelligence.

---

## G03 — Entity Resolution

**Dependencies:** G02 only.

### Goal

Prevent duplicate entities across different research runs.

Example:

Ericsson
Telefonaktiebolaget LM Ericsson
Ericsson AB

must resolve to the same canonical company where evidence supports that resolution.

### Requirements

Every entity receives a stable entity ID.

Initial entities:

- Company
- Person
- Technology
- Project
- Event

### Exit Criteria

Repeated research does not create uncontrolled duplicate graph nodes.

---

## G04 — Governed Relationship Extraction

**Dependencies:** G03 only.

### Goal

Convert governed intelligence into explicit relationships.

Example:

H&M
    PARTNERED_WITH
Google Cloud

### Requirements

A relationship cannot exist without supporting intelligence.

Each relationship must reference its supporting:

- Claim
- Evidence
- Source
- Governance Decision

Relationship support retains temporal provenance (research timestamps,
validity/supersession state) and conflicting governed claims. Conflicts remain
inspectable and cannot become an unqualified edge.

### Fail-Closed Rule

Unsupported relationships are rejected.

BLOCK content must not enter usable graph retrieval.

### Exit Criteria

Relationships are traceable to evidence.

---

## G05 — Knowledge Graph Persistence

**Dependencies:** G04 only.

### Goal

Persist entities and relationships as a reusable graph.

### Minimum Graph Model

Node:

- entity_id
- entity_type
- canonical_name

Edge:

- relationship_id
- source_entity_id
- target_entity_id
- relation_type
- claim_id
- evidence_id
- source_id
- governance_status
- created_at

### Important Constraint

Start local-first.

Do not introduce heavy graph infrastructure unless demonstrated necessary.

Projection is incremental and idempotent: reprocessing the same governed run
is a no-op, while refreshed or superseded support updates only affected graph
nodes, edges, eligibility, and provenance. Canonical research history is never
deleted. Temporal provenance and conflict state survive restart.

### Exit Criteria

The graph survives application restart and can be reconstructed or loaded deterministically.

---

## G06 — Graph Retrieval & GraphRAG

**Dependencies:** G05 only.

### Goal

Answer questions over accumulated company intelligence.

Supported first-stage queries:

- direct relationship
- shared connection
- neighborhood
- cross-company relationship
- multi-hop path
- recurring entity

Examples:

How are Company A and Company B connected?

Which technologies occur across multiple researched companies?

Which companies share the same technology partners?

What evidence connects Company X to Technology Y?

What is the evidence-backed path between Company A and Company B?

### Critical Rule

GraphRAG retrieves from the user's accumulated intelligence base.

It does not automatically search the web for every graph question.

The bounded execution contract is:

```text
Question
→ Entity Resolution
→ Graph Retrieval / bounded Path
→ Supporting Evidence
→ Governed Context
→ LLM Answer
```

G06 never invokes web research or Refresh implicitly.

### Exit Criteria

Answers contain both graph reasoning and supporting provenance.

---

## G07 — Graph Intelligence UI

**Dependencies:** G06 only.

### Goal

Make accumulated knowledge visible and inspectable.

### Views

#### Companies in Memory

Shows user-selected researched companies in order.

#### Company Intelligence

Shows stored intelligence for one company.

#### Connections

Shows entities and relationships connected to the company.

Interactive visualization of nodes and edges.

#### Evidence Inspection

- relation
- supporting claim
- evidence
- source
- governance status
- research date

### Exit Criteria

The graph is useful for inspection, not only visual decoration.

# V1.2 Definition of Done

V1.2 is complete when:

1. User-selected companies persist across sessions.
2. Previous intelligence can be reused without automatic re-search.
3. Explicit refresh is supported.
4. Entities are resolved across research runs.
5. Governed relationships are persisted.
6. Relationships remain traceable to Source → Evidence → Claim.
7. GraphRAG can answer cross-company and multi-hop questions.
8. The graph can be visually inspected.
9. Relationship evidence can be inspected from the UI.
10. GraphRAG performance is evaluated against a non-graph baseline.
11. Existing V1/V1.1 trust and governance behavior remains intact.
